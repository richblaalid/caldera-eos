# L10 Lifecycle Implementation Plan

**Design:** `docs/plans/2026-03-03-l10-lifecycle-design.md`
**Date:** 2026-03-03

## Status

Part 1 (L10 Prep) is already implemented — `l10-prep.ts` generates prep from EOS data, morning briefing cron detects L10 from calendar events, and delivers to `#caldera-eos` channel + partner DMs.

**Remaining work:** Part 2 (Post-Meeting Recap) and Part 3 (Auto-Create EOS Items).

## Phase 1: L10 Recap Agent (Post-Meeting)

### Task 1.1: Create `l10-recap.ts` — recap generation
- **File:** `ember/src/lib/agents/l10-recap.ts`
- Create `generateL10Recap(organizationId, transcriptId)` function
- Input: transcript record from `transcripts` table (full_text + extractions)
- Use `generateObject()` with Sonnet to produce structured recap:
  - `decisions: Array<{ text: string }>`
  - `ids_outcomes: Array<{ issue: string; resolution: string }>`
  - `action_items: Array<{ text: string; owner?: string; due_context?: string }>`
  - `rock_updates: Array<{ rock: string; status_change?: string }>`
  - `key_discussion_points: string[]`
- Include existing Grain `extractions` (from `parseGrainNotes`) as context for the LLM
- Save output via `saveAgentOutput()` with `output_type: 'l10_recap'`, `trust_zone: 1`

### Task 1.2: Create `createAgentTodo()` helper in `agent-runtime.ts`
- **File:** `ember/src/lib/agents/agent-runtime.ts`
- Mirror `createAgentIssue()` pattern: idempotent, dedup by title, prefix with `[Auto-generated by {agentName}]`
- Accept `owner_id`, `due_date`, `organization_id`
- Match owner by first name against `profiles` table (fuzzy match helper)
- Default 7-day due date if not specified

### Task 1.3: EOS item extraction and creation from recap
- **File:** `ember/src/lib/agents/l10-recap.ts`
- After generating recap, extract Issues and To-dos:
  - Issues: from `ids_outcomes` where resolution is "open" or "needs follow-up", plus explicit issues from `extractions.issues`
  - To-dos: from `action_items` with owner matching
- Apply noise guards: max 5 Issues + 5 To-dos, dedup against existing open items
- Create via `createAgentIssue()` and `createAgentTodo()` with source `'L10 Recap'`
- Return counts: `{ issuesCreated, todosCreated, items: Array<{ type, title, owner? }> }`

### Task 1.4: Format L10 recap Slack blocks
- **File:** `ember/src/lib/agents/l10-recap.ts` (or `slack-briefing.ts`)
- `formatL10RecapBlocks(recap, createdItems)` → Block Kit blocks for `#caldera-eos`
- Sections: Decisions, IDS Outcomes, Action Items, Rock Updates
- Footer: "Created X issues and Y to-dos from this L10"

### Task 1.5: Format personal action items DM blocks
- **File:** `ember/src/lib/agents/l10-recap.ts`
- `formatPersonalL10Blocks(partnerName, assignedItems)` → Block Kit blocks for DM
- Only items assigned to that partner
- Header: "From your L10 today:"
- Lists to-dos with due dates and issues

## Phase 2: Wire Recap into Transcript Ingestion Cron

### Task 2.1: Detect new L10 transcripts after ingestion
- **File:** `ember/src/app/api/agents/cron/ingest/transcripts/route.ts`
- After Phase 2 (transcript connector processing), check if any newly-upserted `ingested_data` records have `meeting_type = 'l10'` in payload
- Collect their transcript IDs for recap processing

### Task 2.2: Trigger recap generation + delivery
- **File:** `ember/src/app/api/agents/cron/ingest/transcripts/route.ts`
- For each new L10 transcript detected:
  1. Call `generateL10Recap(organizationId, transcriptId)`
  2. Post recap blocks to `#caldera-eos` via `postBlockMessage()`
  3. For each partner with assigned items, DM their personal action list
- Track delivery to prevent duplicates on cron retry (check `agent_outputs` for existing `l10_recap` with same transcript)
- Add recap stats to cron response: `l10_recaps_sent`, `l10_items_created`

### Task 2.3: Channel ID resolution
- **File:** `ember/src/app/api/agents/cron/ingest/transcripts/route.ts`
- Read `slack_settings.default_channel_id` from partner's org (same pattern as morning briefing L10 prep delivery at line 450)
- Fall back gracefully if no channel configured
